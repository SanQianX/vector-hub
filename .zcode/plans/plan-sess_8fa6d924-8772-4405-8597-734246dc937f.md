# vector-hub v0.2 正式实施计划（UI 定稿 + 五层测试体系）

## 设计基准

**`ui-preview.html`（v3 含全部修正）为 UI 权威设计文档**，正式 `ui/index.html` 与它 1:1（同 token/布局/组件/交互/边界态），仅替换真实 API、移除演示场景切换器。自查原则（同一信息只出现一次、控件贴归属、标签自解释）在实现中持续执行。

## 实施内容

### 一、UI 实现（设计文档 1:1）
- ZCode 风格 token（灰阶四层 + 蓝仅链接 + 红仅危险 + 绿仅成功）、主按钮明度反转
- 248px 侧栏：品牌 → 项目过滤框（>15 出现）→ 项目三态行（选中=整行提亮）→ 导入虚线行 → 底脚健康状态 + 唯一设置入口
- 主区：顶栏 → 全局 banner（未配置/重建进度）→ 搜索 + 类型 chips + 参数 → 紧凑行式结果（中性类型徽章/元信息 +N 截断/片段高亮）
- 文档抽屉：marked 渲染 + frontmatter 元信息头 + 大纲锚点 + 命中块定位高亮 + 关联跳转/返回
- 设置三分区：Embedding / 数据与同步（数据目录+更改、扩展名 chips、防抖）/ 服务只读
- 全套边界态：骨架屏、双空态、未配置禁用+banner、重建进度、12.3k 计数、toast、删除 confirm

### 二、metadata 同步层（src/core/kb-sync.ts）
- 类型推断内建规则（goal/architecture/change/module/index + 目录兜底）
- frontmatter 解析（tags/affectedModules/commit/date/module/title/status → 标量 metadata）
- KbFolderWatcher（递归 fs.watch + 可配置 debounce）；sync/watch/import/重建全走此层

### 三、API 扩展
- SearchResultItem + docType/tags/modules/chunkIndex/chunkCount/file
- /api/search + docTypes 过滤（MetadataFilter $in）
- /api/document（源文件优先/索引副本兜底/404）

### 四、配置体系
- 配置与数据目录分离（~/.vector-hub/config.json，自动迁移旧 data/hub.json）
- 新增 rootPath/extensions/debounceMs；数据目录热切换（停 watcher→新 hub→resume）

## 五层测试体系

**T1 单元**（每次构建）：frontmatter/类型规则/kb-sync metadata 落库/增量同步/docTypes 过滤//api/document 三态/配置迁移/热切换/重建调度 + 现有 14 个回归

**T2 API 契约**（自动化）：11 个端点正常+异常路径全覆盖（400/403/404/500），防前后端契约漂移

**T3 检索质量 golden set**（真实模型）：20~30 条"问题→期望文档"，输出 hit@1/hit@3/MRR，三种模式（纯语义/混合/类型过滤）对比，建立基线供回归

**T4 E2E 自动化**（Playwright devDependency，复用系统 Chrome）：全控件交互断言（搜索/chips/滑杆/勾选/过滤框/导入/设置/抽屉跳转/删除确认/toast）+ 关键界面截图视觉回归 + 三种边界状态注入验证

**T5 性能压测**：小/大索引（合成 500/5000 篇）检索 p50/p95/p99、10/50 并发吞吐与错误率、导入吞吐、watch 响应延迟（<2s 目标）、常驻内存；产出性能报告

**节奏**：T1/T2 每次构建；T3/T4/T5 完成后完整一轮出三份报告（检索质量/性能/E2E 全绿），此后作为回归套件；最后保留一轮用户上手体验（"逻辑是否顺手"的最终判断）

## 执行顺序
1. 配置体系重构 + T1
2. kb-sync + T1
3. API 扩展 + T1/T2
4. UI 1:1 + vendored marked + T4 脚本
5. 真实数据重建 + T3/T5 完整报告 + 浏览器全链路验证

## 交付物
产品代码 + 三份测试报告（检索质量/性能/E2E）+ 可重复的回归测试套件

## 已知影响
- 已导入项目需删除重新导入（metadata 入库）；配置文件位置自动迁移
- Playwright 仅测试依赖，不影响产品零构建运行时
- vectra 上游不动
